# YT Music — мобильное приложение

Android-клиент на Expo + React Native. Работает с тем же API, что и веб-версия.

## Быстрый старт

```bash
npm install
npx expo run:android      # debug-сборка на подключённое устройство
```

Подробности сборки, подписи и настройки адреса бэкенда — в
[`../docs/ANDROID.md`](../docs/ANDROID.md).

## Как всё устроено

```
app/                    экраны (expo-router, файловая маршрутизация)
  (tabs)/               Главная · Обзор · Медиатека · Профиль + мини-плеер
  player.tsx            «Сейчас играет», открывается поверх вкладок
  queue.tsx             очередь воспроизведения
src/
  api/                  клиент, типы (сняты со схем бэкенда), демо-данные
  player/               ядро плеера: очередь, фоновый сервис, ссылки на аудио
  features/             хуки данных (React Query) — компоненты в сеть не ходят
  local/                локальное состояние (MMKV): лайки, недавнее,
                        статистика, настройки, учёт кэша
  ui/theme/             система тем: схема, резолвер, проверки, встроенные темы
  ui/components/        компоненты
themes/                 встроенные темы в JSON — образцы для своих
plugins/                config-plugin: подпись release и разделение по ABI
credentials/            ключ подписи (вне git)
```

### Решения, которые стоит знать

**Очередь — источник правды, а не «текущий трек».** Список и индекс лежат в
`src/player/queueStore.ts`; движок воспроизведения получает только текущий трек
и пару следующих. Целиком очередь в него не заливается: ссылки на аудио живут
час, и у хвоста длинной очереди они успели бы протухнуть.

**Позиция воспроизведения не лежит в глобальном состоянии.** Она обновляется
несколько раз в секунду; компонент, подписанный на неё, перерисовывал бы всё
дерево. Её читают точечно `MiniPlayer` и `Scrubber` через `useProgress()`.

**Истёкшие ссылки чинятся молча.** Ошибка воспроизведения → запрос свежей
ссылки → продолжение с той же секунды. Пользователь ничего не замечает.

**Лайки и «недавнее» — локальные.** На бэкенде персональных лайков пока нет:
`SongResponse.liked` — общий счётчик, а `POST /songs/{id}/like` ничего не делает.
Интерфейс в `src/local/likes.ts` совпадает с будущим серверным, так что переход
на API — замена одной реализации.

**Поиск по медиатеке идёт локально.** Серверный `/songs/search` объявлен как
`list[SongResponse]`, но возвращает YouTube-ответ `{results, query}` — запрос к
нему всегда падает на валидации. Сетевой поиск идёт в `/songs/youtube/search`.

**Демо-режим.** Если бэкенд не отвечает, приложение показывает демо-набор и
играет его — чтобы его можно было открыть и посмотреть, ничего не поднимая.

**Оформление задаётся JSON-ом.** Цвета, форма, шрифт, плотность, варианты
компонентов и анимации описываются одним файлом; тема переключается на лету,
без перезапуска. Формат и что именно можно менять — в
[`themes/README.md`](themes/README.md).

Ключевое следствие для кода: **токены нельзя импортировать напрямую**.
`StyleSheet.create()` запекает значения при загрузке модуля, и тема в рантайме
их уже не изменит. Стили объявляются фабрикой на уровне модуля и берутся
хуком:

```ts
const makeStyles = (t: Theme) => StyleSheet.create({ row: { color: t.colors.text } });

function Row() {
  const styles = useThemedStyles(makeStyles);   // пересобирается на смену темы
}
```

Фабрика обязана быть вне компонента — иначе её ссылка меняется каждый рендер
и мемоизация не работает.

**Смахивание по строке трека.** Вправо — лайк, влево — в очередь. Действие
срабатывает по отпусканию за порогом, а не по его пересечению: жест можно
передумать. Жест активируется только по горизонтали (`activeOffsetX`), иначе
он перехватывал бы вертикальный скролл списка.

**Тактильный отклик** — через `src/ui/haptics.ts`, а не вызовом
`expo-haptics` напрямую: обёртка уважает выключатель в профиле и глушит
ошибки вибромотора. Отклик — украшение, из-за него нажатие падать не должно.

**Статистика локальная.** Серверных счётчиков на пользователя нет: `listened`
и `liked` в API общие по всем. Время прослушивания копится в фоновом сервисе
и ограничено сверху за один тик — иначе долгая пауза засчиталась бы как
прослушивание.

**Ореол под обложкой** (`src/ui/components/Glow.tsx`). Радиального градиента
в React Native нет, а тянуть ради одного эффекта Skia несоразмерно — ореол
собран из десяти вложенных кругов с квадратично падающей непрозрачностью.
Четырёх слоёв мало: между ними видны кольца.

**Доминирующий цвет обложки** берётся из blurhash, который `expo-image` умеет
посчитать на устройстве: хэш с компонентами 1×1 — это ровно усреднённый цвет,
а его первые символы декодируются в RGB (`src/ui/blurhash.ts`). Ни нативного
модуля, ни поля на бэкенде не нужно, картинка к этому моменту уже в кэше.

От обложки берётся **только оттенок** — насыщенность и светлоту задаёт тема,
иначе светлая обложка выбелила бы тёмную тему. Почти серая обложка даёт
нейтральный ореол, а не случайный цвет: подставлять сюда оттенок из хэша id
нельзя, ярко-розовое свечение вокруг чёрно-белого снимка выглядит поломкой.

**Бейдж формата** (`src/features/useTrackFormat.ts`). Кодека и битрейта в API
нет, поэтому размер файла берётся запросом первого байта: `Range: bytes=0-0`
даёт заголовок `Content-Range` с полным размером, а `Content-Type` — тип.
Именно ranged GET, а не HEAD: ссылка подписана для метода GET, смена метода
сломала бы подпись. Битрейт делится на длительность, которую сообщает движок,
а не на метаданные — она измерена по самому файлу.

Признака «из кэша» в бейдже нет: плеер не сообщает, играет ли трек из своего
буфера или из сети.

**Поиск по медиатеке** нечёткий — подпоследовательностью, а не подстрокой:
«bnb» находит Bonobo. Ищет по уже загруженной пагинацией части, а не по всей
базе: серверный поиск сломан (см. ниже).

## Чего в настройках нет и почему

Переключателей «без пауз» (gapless) и «выравнивать громкость» не существует:
первого не требуется — ExoPlayer играет без пауз сам для поддерживаемых
форматов; второй потребовал бы обработки звука, наружу
`react-native-track-player` её не выводит. Из реально управляемого выведены
`androidSkipSilence` и `audioOffload`.

Размер кэша считается обходом каталога (`src/local/cache.ts`): ни `expo-image`,
ни плеер не отдают занятый объём. У `expo-image` есть только
`getCachePathAsync(ключ)` — путь одного файла, не сумма.

`Image.configureCache()` не используется намеренно: он помечен `@platform ios`
и описывает SDWebImage, а на Android под `expo-image` работает Glide — вызов
был бы пустышкой.

## Куда встраивать авторизацию

Бэкендовый модуль `auth` пока пустой. Когда он появится, точка подключения одна —
`configureAuth()` в `src/api/client.ts`: туда передаются функция получения токена
и обработчик 401. Остальной код приложения трогать не нужно.
