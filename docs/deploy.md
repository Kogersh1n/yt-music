## Что было на сервере до нас

Машина уже занята вторым проектом, и он сделан аккуратно — я подстроился под тот
же шаблон, а не стал городить своё:

- **nginx** на 80/443, один сайт: CouchDB (`/opt/obsidian-sync`, Obsidian LiveSync)
- **CouchDB** слушает `127.0.0.1:5984`, наружу его отдаёт только nginx
- **ufw**: разрешены ровно 22, 80, 443
- **certbot 2.9.0**, сертификат на `82-70-63-136.nip.io`
- домен через **nip.io** — покупать ничего не нужно, `<что-угодно>.<ip>.nip.io`
  резолвится в этот IP

Отсюда и решение: ytmusic встаёт по той же схеме — сервисы на петле,
наружу только nginx с TLS.

## Один сервер или второй

**Всё на этом.** Проверил по факту, а не на глаз:

| | |
|---|---|
| память | 1018 МБ занято из 11927 (со всеми контейнерами обоих проектов) |
| диск | 8.1 ГБ из 45 |
| swap | 4 ГБ настроен |

Запаса больше чем в десять раз. Разносить постгрес на вторую машину означало бы
гонять базу по сети между инстансами и открывать её наружу — ровно та дыра,
которую мы только что закрывали.

Единственное, что стоит держать в голове: ядра всего два, а импорт с ютуба
(`yt-dlp` + ffmpeg) — самая прожорливая операция в проекте. Чтобы он не мешал
соседнему проекту, воркеру в compose жёстко ограничен процессор:

```yaml
deploy:
  resources:
    limits:
      cpus: "1.0"
      memory: 1500M
```

Второй инстанс лучше оставить под стенд или что-то другое.

## Почта: Resend — работает

Настроен `Resend` вместо Gmail. В аккаунте нашёлся подтверждённый домен
**`bioauth.site`**, поэтому отправитель `noreply@bioauth.site` — письма уходят
на любой адрес. (Через `onboarding@resend.dev` доставка шла бы только владельцу
аккаунта Resend.)

```
SMTP_HOST=smtp.resend.com
SMTP_PORT=587
SMTP_USERNAME=resend          # у Resend логин всегда буквально "resend"
SMTP_PASSWORD=<API-ключ>
SMTP_SENDER=noreply@bioauth.site
```

**Проверено настоящей отправкой.** Регистрация на `korvoattano67@gmail.com`,
и в API Resend:

```
2026-08-28 19:23:14  ->['korvoattano67@gmail.com']
тема: Verify your email   статус: delivered
```

Проверять пришлось через API Resend, а не по логам: `send_email` глотает
`SMTPException` и пишет только `logging.warning`, поэтому celery отрапортовал
`succeeded` независимо от исхода. Это тот самый молчаливый обработчик,
который стоит починить — иначе о сломанной почте узнаёшь только по жалобам.

### Ключ засветился в переписке

API-ключ Resend был отправлен обычным сообщением. Он лежит на сервере
в `/opt/ytmusic/.env` с правами 600, но сам факт передачи стоит закрыть
ротацией в панели Resend, когда будет удобно — там же меняется значение
`SMTP_PASSWORD`.

## APK — собран и раздаётся с сервера

Собран локально (JDK 21 + Android SDK), подписан твоим ключом из
`mobile/credentials`, а не отладочным:

```
Signer #1 certificate DN: CN=YT Music, OU=Development, O=ytmusic
```

Внутри `assets/app.config` зашит боевой адрес:

```
"apiUrl":"https://ytmusic.82-70-63-136.nip.io"
```

Поскольку он `https`, плагин не включил `usesCleartextTraffic` — release-сборка
осталась строгой, как и задумано в `app.config.ts`.

Благодаря ABI-splits файлов два:

| файл | размер | для кого |
|---|---|---|
| `ytmusic-1.0.0-arm64-v8a.apk` | 41 МБ | любой телефон примерно с 2017 года — **бери этот** |
| `ytmusic-1.0.0-armeabi-v7a.apk` | 34 МБ | старые 32-битные устройства |

### Как скачать без ноутбука

Открыть на телефоне:

**https://ytmusic.82-70-63-136.nip.io/apk/**

Отдаёт nginx с тем же сертификатом, что и API. Проверено снаружи: `HTTP 206`,
тип `application/vnd.android.package-archive`, около 1 МБ/с.

Android спросит разрешение на установку из браузера — это обычное поведение
для APK не из Play Store.

Каталог доступен всем, кто знает адрес. Секретов в APK нет: внутри только
публичный адрес API. Если захочешь закрыть — basic auth в nginx.

### Обновить APK потом

```bash
cd mobile
npx expo prebuild -p android --clean
cd android && ./gradlew assembleRelease
cd ../app/build/outputs/apk/release
cat app-arm64-v8a-release.apk | ssh ubuntu@82.70.63.136 \
  'cat > /var/www/ytmusic-apk/ytmusic-1.0.1-arm64-v8a.apk'
```

Перед сборкой не забудь поднять `versionCode` в `app.config.ts` — иначе
Android не даст поставить новую версию поверх старой.
